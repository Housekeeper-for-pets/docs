# 시터 평점 연동 방법 A/B/C 트레이드오프 — 캐시 컬럼(B) 채택

> 카테고리: 후기·평점 · 2026-06-01~02 · 도메인: 평점 집계

## 문제
시터 평점/리뷰수를 어떻게 노출할지: **A) 실시간 집계 / B) SitterProfile 캐시 컬럼 / C) Redis ZSET** 중 선택해야 했다.

## 결정: 방법 B (캐시 컬럼)
- ① 시터 목록/상세에 이미 **TTL 1h 캐시**가 있어, A의 "실시간성" 장점이 무력화됨.
- ② B의 단점(작성/삭제 시 갱신 로직)은 어차피 `evictSitterDetail()`을 호출하는 자리에 `updateSitterReviewStats()` **한 줄 추가**라 비용이 거의 0.
- ③ `averageRating` 정렬은 **컬럼이 있어야 가능** → B에서만 `sort=averageRating` 확장 가능.

## 증분 vs 전체 재계산
`count+1` 증분은 동시 작성 시 카운트가 꼬인다 → **매번 AVG/COUNT 전체 재계산**으로 분산 락 없이 정합성 확보(리뷰는 저빈도라 비용 허용).

## 알려진 트레이드오프
리뷰 작성/삭제 시 `cache:sitter:{id}`는 무효화하지만 `cache:sitters:*`는 비용 때문에 미무효화 → **목록과 상세의 평점이 최대 1h 다를 수 있음**(의도된 선택).

## 배운 점
정답 알고리즘이 아니라 **이미 깔린 캐시 구조·조회 패턴·확장 요구(정렬)**가 설계를 결정한다. 트레이드오프는 숨기지 말고 명시한다.
