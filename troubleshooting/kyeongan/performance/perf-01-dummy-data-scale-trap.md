# 더미데이터 13건의 함정 — 측정이 이상하면 측정 환경을 먼저 의심하라

> 카테고리: 성능(인덱스) · 2026-06-04 · 도메인: 인덱스 · 부하 테스트

## 문제
EXPLAIN·성능 측정이 무의미했다. 풀스캔을 해도 비용이 0에 가깝고 인덱스 효과가 안 보였다. 5/28 측정에선 캐시 미적용인데도 P99가 20~30ms로 이미 통과해버렸다.

## 원인
**더미데이터가 13건뿐**이라 DB 조회 자체가 6~8ms로 빨라, 인덱스/캐시 효과가 측정 노이즈에 묻혔다.

## 추가: ddl-auto: create 함정
local 프로파일이 `create`라 앱 재기동마다 테이블이 drop·재생성 → **더미데이터·인덱스가 매번 날아갔다**. 재기동(특히 캐시 토글) 후엔 항상 `COUNT`부터 확인하고 측정하는 절차를 고정했다.

## 해결
시터·공고 각 **1만~10만 건**을 삽입하되, 단순히 양만 늘리는 게 아니라 **운영 분포를 모사**(예: 공고 status OPEN:CLOSED ≈ 1:9)해 선택도를 현실화한 뒤 EXPLAIN·부하 측정.
> 분포를 현실화하자 인덱스 설계 방향이 통째로 바뀐 상세는 → [perf-04: 운영 분포 모사](./perf-04-realistic-data-distribution.md)

## 배운 점
**측정이 이상하면 측정 대상보다 측정 환경(데이터 규모 + 분포)을 먼저 의심하라.** 규모를 키우자 P99 3.5초 → 70ms 차이가 또렷이 드러났고, 분포를 운영과 맞추자 인덱스 설계 자체가 달라졌다.
