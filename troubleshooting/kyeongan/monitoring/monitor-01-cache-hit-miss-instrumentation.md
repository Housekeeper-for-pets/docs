# 캐시 hit/miss를 못 세는 구조적 이유 — @Cacheable은 프록시 바깥에서 돈다

> 카테고리: 모니터링 · 2026-06-09 · 도메인: 캐싱 계측 (가장 많이 배운 케이스)

## 문제
캐시 적중률을 재려고 서비스 메서드에 카운터를 박았더니 **miss만 세어지고 hit은 영원히 0**이었다.

## 원인 (두 가지가 겹침)
- ① `@Cacheable`은 **캐시 미스일 때만 메서드 본문이 실행**된다. 히트면 Spring 프록시가 가로채 캐시값을 바로 돌려주므로 **내 메서드가 아예 안 돈다** → miss만 카운트.
- ② Micrometer 자동 캐시 계측은 **RedisCache를 지원하지 않는다**(Caffeine과 달리 통계 내장 없음).

## 해결
hit/miss가 동시에 보이는 유일한 지점인 Spring Cache 추상화의 **`Cache.get()`**을 감싸는 데코레이터(`MeteredCache`)를 만들고, **`CacheManager` 레벨에서 통째로 래핑(`MeteredCacheManager`)**. CacheManager에서 감싸니 이후 캐시가 추가돼도 자동 계측된다. 태그는 **캐시명만**(키 제외 → 시계열 카디널리티 폭발 방지).

## 배운 점
"**계측을 어디에 박을지**"는 기능 위치가 아니라 **프레임워크가 어느 레이어(프록시/추상화)에서 동작하는지**를 따라가야 한다. `@Cacheable`이 메서드 바깥에서 도는 걸 모르면 영원히 절반만 센다.
