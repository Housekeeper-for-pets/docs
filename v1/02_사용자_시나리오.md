## 페르소나 설계 원칙

ForPets의 페르소나는 단순한 "가상 사용자"가 아니라, **우리가 구현할 기능이 왜 필요한지를 증명하는 존재**다.
각 페르소나가 겪는 Pain Point가 곧 우리의 기술적 도전 과제와 1:1로 매핑된다.

| 페르소나 | 핵심 연결 기능 |
|----------|----------------|
| 페르소나 1 — 김보호 (보호자) | 역방향 매칭 공고, Redisson 동시 입찰, Kafka 매칭 확정, SSE 케어 일지 |
| 페르소나 2 — 박시터 (시터) | 제안 입찰 동시성, AI 프로필 자동 생성, 케어 일지 실시간 전송 |
| 페르소나 3 — 이탐색 (탐색형 보호자) | QueryDSL 동적 검색, Redis 캐싱, AI 시맨틱 검색 (RAG) |
| 페르소나 4 — 최구조 (구조단체 관리자) | 임시보호 공고, Kafka 매칭 이벤트, 관리자 권한 처리 |

## 페르소나 1 — "꼭 맞는 집사를 찾고 싶어" 김보호

### 프로필

| 항목 | 내용 |
|------|------|
| 이름 | 김보호 |
| 나이 | 32세 |
| 직업 | IT 스타트업 PM |
| 반려동물 | 말티즈 3살 (이름: 뭉치), 분리불안이 심한 편 |
| 특징 | 해외 출장이 잦아 케어 서비스를 자주 이용한다. 수십 개 시터 프로필을 뒤지는 게 너무 피곤해서 "내 조건에 맞는 제안을 받고 싶다"는 니즈가 강함. |

### Goal

> **내 반려동물의 특성에 딱 맞는 시터를 빠르게 찾아서, 출장 기간 안심하고 맡기고 싶다.**

- 조건을 한 번만 입력하면 시터들이 먼저 제안해 주길 원함
- 케어 중에도 뭉치 상태를 실시간으로 확인하고 싶음
- 믿을 수 있는 시터인지 후기와 평점으로 검증하고 싶음

### Pain Point

| # | 기존 서비스에서 겪는 불편함 | 연결 기능 |
|---|---------------------------|-----------|
| 1 | 케어네이처, 펫시팅닷컴에서 수십 개 시터 프로필을 직접 탐색해야 함. "분리불안 노령견 경험" 조건으로 필터가 안 됨 | **역방향 매칭 공고** — 조건 등록 후 시터가 역으로 제안. AI RAG 시맨틱 탐색 |
| 2 | 시터가 뭉치를 제대로 케어하는지 중간에 알 수가 없음. 문자 한 번 오면 다행 | **SSE 실시간 케어 일지** — 시터가 사진·일지 올리면 보호자에게 즉시 푸시 |
| 3 | 여러 서비스를 다 가입해야 함. 시터·렌탈·임시보호가 다 따로 | **통합 케어 플랫폼** — 시터 매칭 + 용품 렌탈 + 임시보호를 하나의 앱에서 |

### 주요 사용 시나리오

#### 시나리오 1-1: 역방향 시터 매칭 공고 등록

```
상황: 보호 씨가 다음 주 3박 4일 해외 출장 전, 뭉치를 맡길 시터를 구해야 한다.

1. ForPets 앱에서 "케어 공고 등록" 클릭
2. 케어 조건 입력:
   - 반려동물: 뭉치 (말티즈 3살, 분리불안)
   - 기간: 7/1(화) ~ 7/4(금), 3박 4일
   - 지역: 서울 마포구
   - 예산: 최대 6만원
   - 요구사항: "분리불안 있어요. 하루 2회 이상 산책 부탁드려요."
3. 공고 등록 완료 → 시스템이 조건 맞는 시터 12명에게 SSE 알림 발송
4. 보호 씨: 공고 화면에서 실시간으로 시터 제안이 들어오는 것 확인

→ 기술 연결: CarePosting 공고 등록, SSE 시터 알림, QueryDSL 조건 매칭
```

#### 시나리오 1-2: 시터 제안 비교 후 선택

```
상황: 공고 등록 30분 후, 제안이 3건 들어왔다.

1. 제안 목록 확인:
   - 박시터: 4.5만원 / "소형견 전문, 말티즈 케어 경험 다수" / 후기 98개 ⭐4.9
   - 이시터: 4.0만원 / "홍대 근처, 분리불안 케어 경험 있음" / 후기 42개 ⭐4.7
   - 최시터: 5.5만원 / "수의대 출신, 응급처치 가능" / 후기 15개 ⭐4.8
2. AI 추천: "박시터님이 분리불안 케어 후기가 23건으로 가장 많아요 (출처: 후기 #142)"
3. 보호 씨: 박시터 선택 → "제안 수락" 클릭
4. 시스템: Kafka 매칭 확정 이벤트 발행
   → 결제 처리 + 박시터·보호 씨 양쪽 SSE 알림 + 케어 일정 생성 비동기 병렬 처리
5. 매칭 확정! "박시터님과 케어가 확정되었습니다."

→ 기술 연결: Redisson 분산 락 (동시 수락 정합성), Kafka 매칭 확정 이벤트, SSE 알림
```

#### 시나리오 1-3: 케어 중 실시간 일지 수신

```
상황: 출장 중인 보호 씨가 뭉치 상태가 궁금하다.

1. 박시터가 포펫츠 앱에서 케어 일지 등록:
   "뭉치 오늘 산책 2회 했어요! 밥도 잘 먹었습니다. 🐶"
   + 뭉치 사진 2장 첨부
2. 시스템: SSE로 보호 씨 앱에 즉시 푸시 알림
3. 보호 씨: "이미지 + 일지 내용" 실시간 확인
4. 안심하며 업무 집중

→ 기술 연결: SSE(Server-Sent Events), CareLog 엔티티 저장, Redis Pub/Sub
```

#### 시나리오 1-4: 용품 렌탈 공동 이용

```
상황: 뭉치를 위한 이동용 켄넬이 없어서 렌탈을 알아본다.

1. 렌탈 탭에서 "중형 켄넬" 검색
2. 7/1~7/4 기간으로 렌탈 신청
3. 시스템: Redisson 재고 락으로 동시 신청 정합성 보장
4. 렌탈 확정 (총 3일 × 8,000원 = 24,000원)
5. 7/4 반납 기한 초과 시 → 스케줄러가 자동 감지 → 하루당 50% 추가 패널티 자동 부과

→ 기술 연결: Redisson 재고 락, 스케줄러 반납 지연 감지, 패널티 자동 부과
```

## 페르소나 2 — "신뢰받는 집사가 되고 싶어" 박시터

### 프로필

| 항목 | 내용 |
|------|------|
| 이름 | 박시터 |
| 나이 | 28세 |
| 직업 | 프리랜서 디자이너 + 펫시터 부업 |
| 특징 | 소형견 케어 경험 3년. 말티즈·포메라니안 전문. 좋은 후기를 쌓아서 전업 펫시터로 전환하고 싶음. 기존 플랫폼은 시터 프로필 작성이 너무 복잡하고, 공고가 내 조건에 맞는지 하나하나 필터하기 귀찮음. |

### Goal

> **내 전문성을 잘 보여주는 프로필로, 나에게 딱 맞는 케어 공고를 받아서 꾸준히 일하고 싶다.**

- 프로필이 내 전문성을 잘 드러내야 보호자가 선택해줌
- 내 조건(지역, 기간, 견종)에 맞는 공고를 빠르게 발견하고 싶음
- 케어 일지를 쉽게 올릴 수 있어야 신뢰를 쌓을 수 있음

### Pain Point

| # | 기존 서비스에서 겪는 불편함 | 연결 기능 |
|---|---------------------------|-----------|
| 1 | 프로필 문구를 어떻게 써야 보호자 눈에 띄는지 모르겠음. 글 솜씨가 없어서 매력적인 소개글 작성이 어려움 | **AI 시터 프로필 자동 생성** — 경력·특기 입력 → LLM이 카테고리별 신뢰감 있는 프로필 문구 자동 생성 |
| 2 | 공고가 올라오면 바로 알림이 안 와서 늦게 발견함. 이미 다른 시터가 먼저 제안해버린 경우가 많음 | **SSE 공고 알림** — 조건 맞는 공고 등록 시 즉시 실시간 푸시 |
| 3 | 케어 기간 중 일지 올리기가 불편함. 앱이 느리고 사진 업로드가 자주 실패함 | **케어 일지 SSE 연동** — 일지 등록 → 보호자에게 SSE 즉시 전달 |

### 주요 사용 시나리오

#### 시나리오 2-1: AI 시터 프로필 자동 생성

```
상황: 박시터가 포펫츠에 처음 가입하고 시터 프로필을 작성해야 한다.

1. "프로필 작성" 클릭 → AI 자동 생성 버튼 선택
2. 경력·특기 입력:
   - 전문 견종: 말티즈, 포메라니안
   - 경력: 3년
   - 특기: 분리불안 케어, 하루 3회 산책
3. 시스템: LLM에 카테고리별 프롬프트 전송
   (소형견 전문 톤: "귀엽고 섬세한 케어" 강조)
4. AI 생성 결과 (JSON 구조화 출력):
   {
     "title": "소형견 케어 전문 집사 박시터",
     "description": "말티즈·포메라니안 3년 케어 경험. 분리불안 있는 아이도 안심하고 맡겨주세요...",
     "specialties": ["분리불안 케어", "소형견 전문", "하루 3회 산책"],
     "keywords": ["말티즈", "포메", "집사", "분리불안"]
   }
5. 박시터: 내용 확인 후 저장

→ 기술 연결: Spring AI, LLM 구조화 출력 (필수 1), 프롬프트 분기 (소형견/노령견/의료케어)
```

#### 시나리오 2-2: 공고 알림 수신 후 제안 입찰

```
상황: 박시터가 디자인 작업 중, 스마트폰에 알림이 왔다.

1. SSE 알림: "조건 맞는 새 공고가 등록되었습니다! [말티즈 3살, 마포구, 7/1~7/4, 예산 6만원]"
2. 공고 상세 확인: 보호 씨의 케어 공고 내용 열람
3. 제안 입찰:
   - 제안 금액: 4만 5천원
   - 메시지: "말티즈 케어 경험이 많습니다. 분리불안 전문이에요. 하루 3회 산책 가능합니다."
4. 시스템: Redisson 분산 락으로 동시 제안 정합성 보장
   (같은 시간에 여러 시터가 제안해도 proposal_count 정확히 집계)
5. "제안이 등록되었습니다." 확인

→ 기술 연결: SSE 실시간 공고 알림, Redisson 분산 락 (proposal_count 정합성)
```

## 페르소나 3 — "딱 맞는 시터를 검색으로 찾고 싶어" 이탐색

### 프로필

| 항목 | 내용 |
|------|------|
| 이름 | 이탐색 |
| 나이 | 35세 |
| 직업 | 자영업자 |
| 반려동물 | 진돗개 7살 (이름: 돌이), 노령견으로 관절이 좋지 않음 |
| 특징 | 특정 케어 서비스를 정해두고 오기보다, "노령견 전문", "관절 케어 경험" 등 조건으로 시터를 탐색하는 스타일. |

### Goal

> **우리 돌이에게 딱 맞는 노령견 케어 경험 있는 시터를 자연어로 빠르게 찾고 싶다.**

### Pain Point

| # | 기존 서비스에서 겪는 불편함 | 연결 기능 |
|---|---------------------------|-----------|
| 1 | "노령견 케어 경험 있음"으로 검색해도 관련 없는 시터만 잔뜩 나옴. 키워드 검색이 너무 단순함 | **AI RAG 시맨틱 검색** — 후기·프로필 벡터 탐색으로 맥락 기반 시터 탐색 |
| 2 | 같은 조건으로 여러 번 검색하면 매번 느림 | **Redis 캐싱** — 동일 조건 재검색 시 DB 조회 없이 즉시 응답 |
| 3 | AI 챗봇에게 물어봤더니 존재하지 않는 시터를 추천해줌 | **환각 방어** — AI 추천 결과를 DB 교차 검증 후 불일치 시 차단 |

### 주요 사용 시나리오

#### 시나리오 3-1: AI 시맨틱 시터 탐색

```
상황: 탐색 씨가 돌이를 맡길 시터를 AI 챗봇에게 자연어로 요청한다.

1. AI 챗봇 입력: "관절이 안 좋은 7살 진돗개 케어해줄 시터 찾아줘. 마포구에서."
2. [Tool Calling] searchSitters(location="마포", petSize="LARGE", specialty="노령견") 호출
3. [RAG] "관절 케어", "노령견" 키워드로 시터 후기 벡터 시맨틱 탐색
   → "이 시터는 관절炎 있는 노령견 케어 후기가 15건이에요 (출처: 후기 #87)"
4. AI 응답 (SSE 스트리밍):
   "관절 케어 경험이 있는 시터 2명을 찾았어요.
    1. 김시터 — '14살 진돗개 2주 케어' 후기 있음, 마포구 거주
    2. 오시터 — 수의보조 자격증 보유, 노령견 전문"
5. 탐색 씨: 1번 시터 클릭 → 공고 등록으로 연결

→ 기술 연결: Tool Calling (필수 2), RAG 파이프라인 (도전 1), SSE 스트리밍 (도전 2),
             환각 방어 (DB 교차 검증)
```

#### 시나리오 3-2: 캐시 히트로 빠른 재검색

```
상황: 탐색 씨가 "마포구 노령견 시터" 조건으로 두 번째 검색한다.

1. [첫 번째 요청] DB 조회 → 결과 반환 + Redis 캐싱 (TTL 5분)
2. 결과를 훑어보다가 동일 조건으로 재검색
3. [두 번째 요청] Redis 캐시 히트 → DB 조회 없이 즉시 응답 (< 50ms)

→ 기술 연결: Redis 캐싱 (TTL 5분), 캐시 키 설계 (조건 + 페이지 + 정렬)
```

## 페르소나 4 — "유기동물을 위한 임시 집을 찾아요" 최구조

### 프로필

| 항목 | 내용 |
|------|------|
| 이름 | 최구조 |
| 나이 | 40세 |
| 직업 | 비영리 유기동물 구조단체 운영자 |
| 특징 | 매달 5~10마리의 유기동물을 임시보호자에게 연결하는 업무를 담당. 현재는 SNS DM으로 임시보호자를 모집하고 있어 관리가 매우 비효율적. |

### Goal

> **임시보호 공고를 체계적으로 올리고, 조건에 맞는 임시보호자를 빠르게 연결하고 싶다.**

### Pain Point

| # | 기존 서비스에서 겪는 불편함 | 연결 기능 |
|---|---------------------------|-----------|
| 1 | 인스타 DM, 카카오톡 오픈채팅으로 임시보호자 모집. 관리가 전혀 안 됨 | **임시보호 공고 등록** — 체계적 공고 + 지원자 관리 |
| 2 | 지원자가 조건에 맞는지 하나하나 직접 확인해야 함 | **Kafka 매칭 이벤트** — 조건 매칭 시 자동 알림 + 확정 처리 |
| 3 | ADMIN 기능이 없어서 공고 관리·지원자 확인에 불편함 | **관리자 권한 (RESCUE 역할)** — 구조단체 전용 공고 등록·관리 기능 |

### 주요 사용 시나리오

#### 시나리오 4-1: 임시보호 공고 등록

```
상황: 구조된 포메라니안 2살을 위한 임시보호자를 모집해야 한다.

1. ForPets 앱 → "임시보호 공고 등록" (RESCUE 권한)
2. 공고 정보 입력:
   - 동물명: 솜이 (포메라니안, 2살, 암컷, 중성화 완료)
   - 기간: 6/15 ~ 7/15 (1개월)
   - 조건: 아파트 가능, 선임묘 없는 가정 선호
3. 공고 등록 완료 → 조건 맞는 보호자 후보 자동 탐색 + 알림 발송
4. 지원자 8명 확인 → 조건 일치 3명 추천
5. 최종 임시보호자 선정 → Kafka 매칭 확정 이벤트 발행

→ 기술 연결: TempCarePosting 등록 (RESCUE 권한), Kafka 매칭 이벤트, SSE 알림
```
