## 페르소나 설계 원칙

ForPets의 페르소나는 단순한 "가상 사용자"가 아니라, **우리가 구현할 기능이 왜 필요한지를 증명하는 존재**다.
각 페르소나가 겪는 Pain Point가 곧 우리의 기술적 도전 과제와 1:1로 매핑된다.

### v1 MVP 페르소나

| 페르소나 | 핵심 연결 기능 |
|----------|----------------|
| 페르소나 1 — 역방향 보호자 | 역방향 매칭 공고, DB Unique 동시 입찰, Kafka 매칭 확정, SSE 케어 일지 |
| 페르소나 2 — 순방향 보호자 | 시터 동적 검색 (QueryDSL), Redis 캐싱, 케어 신청·매칭 |
| 페르소나 3 — 시터 | SSE 공고 알림, 제안 입찰, 케어 일지 |

### 확장 기능 페르소나 (v1 완료 후)

| 페르소나 | 핵심 연결 기능 |
|----------|----------------|
| 페르소나 3 — 시터 (추가) | AI 프로필 자동 생성 |
| 페르소나 4 — 구조단체 관리자 | 임시보호 공고, Kafka 매칭 이벤트, RESCUE 권한 |

# ✅ v1 MVP 페르소나

---

## 페르소나 1 — "내 조건에 맞는 시터가 먼저 제안해줬으면" (역방향 보호자)

### 프로필

| 항목 | 내용 |
|------|------|
| 나이 | 32세 |
| 직업 | IT 스타트업 PM |
| 반려동물 | 말티즈 3살 (분리불안 심함) |
| 특징 | 해외 출장이 잦아 케어 서비스를 자주 이용. 수십 개 시터 프로필을 뒤지는 게 너무 피곤해서 "내 조건에 맞는 제안을 받고 싶다"는 니즈가 강함. |

### Goal

> **내 반려동물의 특성에 딱 맞는 시터를 빠르게 찾아서, 출장 기간 안심하고 맡기고 싶다.**

### Pain Point

| # | 기존 서비스에서 겪는 불편함 | 연결 기능 |
|---|---------------------------|-----------|
| 1 | 수십 개 시터 프로필을 직접 탐색해야 함. "분리불안 노령견 경험" 조건으로 필터가 안 됨 | **역방향 매칭 공고** — 조건 등록 후 시터가 역으로 제안 |
| 2 | 시터가 반려동물을 제대로 케어하는지 중간에 알 수가 없음 | **SSE 실시간 케어 일지** — 시터가 사진·일지 올리면 즉시 푸시 |

### 주요 사용 시나리오

#### 시나리오 1-1: 역방향 시터 매칭 공고 등록

```
상황: 다음 주 3박 4일 해외 출장 전, 반려동물을 맡길 시터를 구해야 한다.

1. ForPets 앱에서 "케어 공고 등록" 클릭
2. 케어 조건 입력:
   - 반려동물: 말티즈 3살 (분리불안)
   - 기간: 7/1(화) ~ 7/4(금), 3박 4일
   - 지역: 서울 마포구
   - 예산: 최대 6만원
   - 요구사항: "분리불안 있어요. 하루 2회 이상 산책 부탁드려요."
3. 공고 등록 완료 → 시스템이 조건 맞는 시터들에게 SSE 알림 발송
4. 공고 화면에서 실시간으로 시터 제안이 들어오는 것 확인

→ 기술 연결: CarePosting 공고 등록, SSE 시터 알림, QueryDSL 조건 매칭
```

#### 시나리오 1-2: 시터 제안 비교 후 선택 (매칭 확정)

```
상황: 공고 등록 30분 후, 제안이 3건 들어왔다.

1. 제안 목록 확인 (가격 오름차순):
   - 시터 A: 4.0만원 / "홍대 근처, 분리불안 케어 경험 있음" / 후기 42개 ⭐4.7
   - 시터 B: 4.5만원 / "소형견 전문, 말티즈 케어 경험 다수" / 후기 98개 ⭐4.9
   - 시터 C: 5.5만원 / "수의대 출신, 응급처치 가능" / 후기 15개 ⭐4.8
2. 후기와 평점을 보고 시터 B 선택 → "제안 수락" 클릭
3. 시스템: Kafka 매칭 확정 이벤트 발행
   → 결제 처리 + 양쪽 SSE 알림 + 케어 일정 생성 비동기 병렬 처리
   → DB Unique 제약(posting_id UNIQUE)으로 중복 확정 방지
4. 매칭 확정! "시터 B님과 케어가 확정되었습니다."

→ 기술 연결: DB Unique 제약 (매칭 중복 방지), Kafka 매칭 확정 이벤트, SSE 알림
```

#### 시나리오 1-3: 케어 중 실시간 일지 수신

```
상황: 출장 중에 반려동물 상태가 궁금하다.

1. 시터가 포펫츠 앱에서 케어 일지 등록:
   "오늘 산책 2회 했어요! 밥도 잘 먹었습니다. 🐶"
   + 사진 2장 첨부
2. 시스템: SSE로 보호자 앱에 즉시 푸시 알림
3. 보호자: "이미지 + 일지 내용" 실시간 확인, 안심하며 업무 집중

→ 기술 연결: SSE(Server-Sent Events), CareLog 엔티티 저장, Redis Pub/Sub
```

#### 시나리오 1-4: 케어 완료 후 양방향 후기 작성

```
상황: 케어가 끝나고 보호자가 완료를 확인한다.

1. 보호자: "케어 완료 확인" 클릭 → Reservation 상태 → COMPLETED
2. 보호자: 별점 5점 + 후기 작성 가능
3. 시터: 보호자에 대한 후기 작성 가능 (양방향)
4. 후기 저장 → Redis ZSET 시터 평점 갱신 (ZINCRBY)

→ 기술 연결: Reservation 상태 전이 (COMPLETED), 양방향 Review 엔티티, Redis ZSET
```

## 페르소나 2 — "딱 맞는 시터를 직접 검색해서 신청하고 싶어" (순방향 보호자)

### 프로필

| 항목 | 내용 |
|------|------|
| 나이 | 35세 |
| 직업 | 자영업자 |
| 반려동물 | 진돗개 7살 (노령견, 관절 좋지 않음) |
| 특징 | 공고를 올리기보다 원하는 조건으로 시터를 직접 검색해서 신청하는 스타일. |

### Goal

> **우리 반려동물에게 딱 맞는 노령견 케어 경험 있는 시터를 조건 검색으로 빠르게 찾고 직접 신청하고 싶다.**

### Pain Point

| # | 기존 서비스에서 겪는 불편함 | 연결 기능 |
|---|---------------------------|-----------|
| 1 | "노령견 케어 경험 있음"으로 검색해도 관련 없는 시터만 잔뜩 나옴 | **QueryDSL 동적 검색** — 지역·견종·경력 등 복합 조건 필터 |
| 2 | 같은 조건으로 여러 번 검색하면 매번 느림 | **Redis 캐싱** — 동일 조건 재검색 시 즉시 응답 |

### 주요 사용 시나리오

#### 시나리오 2-1: 시터 직접 검색 후 케어 신청 (순방향)

```
상황: 노령견을 맡길 시터를 조건으로 직접 검색한다.

1. 시터 검색 조건 입력:
   - 지역: 서울 마포구
   - 반려동물 크기: LARGE
   - 경력: 3년 이상
2. QueryDSL 동적 필터로 시터 목록 조회
   → Redis 캐시 히트 시 즉시 반환 (TTL 1시간)
3. 시터 A 프로필 확인 — 노령견 케어 경험 다수, ⭐4.8
4. "케어 신청" 클릭 → 케어 일정(날짜·내용) 입력
5. 시터 A: 신청 확인 후 수락
6. 매칭 확정 → 케어 진행

→ 기술 연결: QueryDSL 동적 검색, Redis 캐싱 (TTL 1시간), 순방향 케어 신청·수락
```

#### 시나리오 2-2: 케어 완료 후 양방향 후기 작성

```
상황: 케어가 완료되었다.

1. 보호자: "케어 완료 확인" 클릭 → Reservation 상태 → COMPLETED
2. 보호자와 시터 모두 후기 작성 가능
3. Redis ZSET 시터 평점 갱신

→ 기술 연결: Reservation COMPLETED 상태 전이, 양방향 후기
```

## 페르소나 3 — "신뢰받는 집사가 되고 싶어" (시터)

### 프로필

| 항목 | 내용 |
|------|------|
| 나이 | 28세 |
| 직업 | 프리랜서 디자이너 + 펫시터 부업 |
| 특징 | 소형견 케어 경험 3년. 말티즈·포메라니안 전문. 좋은 후기를 쌓아서 전업 펫시터로 전환하고 싶음. |

### Goal

> **내 전문성을 잘 보여주는 프로필로, 나에게 딱 맞는 케어 공고나 신청을 받아서 꾸준히 일하고 싶다.**

### Pain Point (v1 범위)

| # | 기존 서비스에서 겪는 불편함 | 연결 기능 |
|---|---------------------------|-----------|
| 1 | 공고가 올라오면 바로 알림이 안 와서 늦게 발견함 | **SSE 공고 알림** — 조건 맞는 공고 등록 시 즉시 실시간 푸시 |
| 2 | 케어 기간 중 일지 올리기가 불편함 | **케어 일지 SSE 연동** — 일지 등록 → 보호자에게 SSE 즉시 전달 |

### 주요 사용 시나리오

#### 시나리오 3-1: 공고 알림 수신 후 제안 입찰

```
상황: 디자인 작업 중, 스마트폰에 알림이 왔다.

1. SSE 알림: "조건 맞는 새 공고가 등록되었습니다! [말티즈 3살, 마포구, 7/1~7/4, 예산 6만원]"
2. 공고 상세 확인
3. 제안 입찰:
   - 제안 금액: 4만 5천원
   - 메시지: "말티즈 케어 경험이 많습니다. 분리불안 전문이에요."
4. 시스템: DB Unique 처리로 동일 시터 중복 제안 방지
5. "제안이 등록되었습니다." 확인
6. 보호자에게 SSE 알림 발송: "새 제안이 도착했습니다!"

→ 기술 연결: SSE 실시간 공고 알림, DB Unique (중복 제안 방지), SSE 보호자 알림
```

#### 시나리오 3-2: 케어 일지 등록

```
상황: 케어 중 일지를 등록한다.

1. 케어 일지 내용 + 사진 2장 입력
2. 시스템: CareLog DB 저장 → SSE로 보호자에게 즉시 전송
3. 보호자가 실시간으로 확인

→ 기술 연결: SSE, CareLog 엔티티, Redis Pub/Sub
```

## 페르소나 3 추가 시나리오 — AI 프로필 자동 생성 (시터, 확장)

### Pain Point (확장 범위)

| # | 기존 서비스에서 겪는 불편함 | 연결 기능 |
|---|---------------------------|-----------|
| 1 | 프로필 문구를 어떻게 써야 보호자 눈에 띄는지 모르겠음 | **AI 시터 프로필 자동 생성** — LLM 구조화 출력 |

#### 시나리오 3-3: AI 시터 프로필 자동 생성

```
상황: 포펫츠에 처음 가입하고 시터 프로필을 작성해야 한다.

1. "프로필 작성" → AI 자동 생성 버튼 선택
2. 경력·특기 입력: 전문 견종, 경력 연수, 특기 사항
3. LLM에 카테고리별 프롬프트 전송 (소형견 전문 톤)
4. AI 생성 결과 (JSON 구조화 출력):
   { "title", "description", "specialties", "keywords" }
5. 내용 확인 후 저장

→ 기술 연결: Spring AI, LLM 구조화 출력, 프롬프트 분기 (소형견/노령견/의료케어)
```

## 페르소나 4 — "유기동물을 위한 임시 집을 찾아요" (구조단체 관리자, 확장)

### 프로필

| 항목 | 내용 |
|------|------|
| 나이 | 40세 |
| 직업 | 비영리 유기동물 구조단체 운영자 |
| 특징 | 매달 5~10마리의 유기동물을 임시보호자에게 연결. 현재는 SNS DM으로 모집하고 있어 관리가 매우 비효율적. |

### Goal

> **임시보호 공고를 체계적으로 올리고, 조건에 맞는 임시보호자를 빠르게 연결하고 싶다.**

### Pain Point

| # | 기존 서비스에서 겪는 불편함 | 연결 기능 |
|---|---------------------------|-----------|
| 1 | SNS DM으로 임시보호자 모집. 관리가 전혀 안 됨 | **임시보호 공고 등록** — 체계적 공고 + 지원자 관리 |
| 2 | 지원자가 조건에 맞는지 하나하나 직접 확인해야 함 | **Kafka 매칭 이벤트** — 조건 매칭 시 자동 알림 + 확정 처리 |

### 주요 사용 시나리오

#### 시나리오 4-1: 임시보호 공고 등록

```
상황: 구조된 포메라니안 2살을 위한 임시보호자를 모집해야 한다.

1. "임시보호 공고 등록" (RESCUE 권한)
2. 공고 정보 입력: 동물명, 종, 나이, 기간, 조건(아파트 가능 여부 등)
3. 공고 등록 → 조건 맞는 보호자 후보 자동 탐색 + SSE 알림 발송
4. 지원자 목록 확인 후 최적 임시보호자 선정
5. Kafka 임시보호 매칭 확정 이벤트 발행

→ 기술 연결: TempCarePosting 등록 (RESCUE 권한), Kafka 매칭 이벤트, SSE 알림
```
