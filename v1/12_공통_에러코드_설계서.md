## 설계 원칙

| 원칙 | 내용 |
|------|------|
| 비즈니스 에러 / 시스템 에러 분리 | `BusinessException` 계층과 미처리 `Exception` 계층을 핸들러에서 구분 |
| 에러코드 단일 정의 | 모든 에러는 `ErrorCode` enum 한 곳에서 관리. 코드 문자열 하드코딩 금지 |
| 공통 응답 구조 통일 | 성공·실패 모두 `ApiResponse<T>` 사용 |
| 401은 Security 필터에서 처리 | JWT 인증 실패는 `@ExceptionHandler` 도달 전에 `JwtAuthEntryPoint`에서 처리 |
| 429는 별도 예외 클래스 | Redisson 락 획득 실패는 `TooManyRequestsException`으로 분리 |

## 2. 공통 응답 구조 — ApiResponse\<T\>

성공·실패 모두 `ApiResponse<T>`로 통일한다.

```java
// global/common/ApiResponse.java
@Getter
@RequiredArgsConstructor
public class ApiResponse<T> {

    private final boolean success;
    private final T data;
    private final String message;
    private final String code;

    /** 성공 응답 */
    public static <T> ApiResponse<T> ok(T data) {
        return new ApiResponse<>(true, data, "OK", "200");
    }

    public static <T> ApiResponse<T> created(T data) {
        return new ApiResponse<>(true, data, "Created", "201");
    }

    /** 실패 응답 */
    public static <T> ApiResponse<T> fail(ErrorCode errorCode) {
        return new ApiResponse<>(false, null, errorCode.getMessage(), errorCode.getCode());
    }

    public static <T> ApiResponse<T> fail(ErrorCode errorCode, String detailMessage) {
        return new ApiResponse<>(false, null, detailMessage, errorCode.getCode());
    }
}
```

**성공 응답 JSON:**
```json
{
  "success": true,
  "data": { "postingId": 10, "title": "말티즈 3박 4일 케어", "status": "OPEN" },
  "message": "OK",
  "code": "200"
}
```

**실패 응답 JSON:**
```json
{
  "success": false,
  "data": null,
  "message": "이미 마감된 공고입니다.",
  "code": "PO003"
}
```

**@Valid 유효성 실패 응답 JSON:**
```json
{
  "success": false,
  "data": {
    "errors": [
      { "field": "budget", "message": "예산은 0 이상이어야 합니다." },
      { "field": "startDate", "message": "케어 시작일은 필수입니다." }
    ]
  },
  "message": "입력값이 올바르지 않습니다.",
  "code": "G001"
}
```

## 3. Exception 계층 구조

```java
// global/exception/BusinessException.java
@Getter
public class BusinessException extends RuntimeException {

    private final ErrorCode errorCode;

    public BusinessException(ErrorCode errorCode) {
        super(errorCode.getMessage());
        this.errorCode = errorCode;
    }

    public BusinessException(ErrorCode errorCode, String detailMessage) {
        super(detailMessage);
        this.errorCode = errorCode;
    }
}
```

```java
// 공통 예외 클래스
public class NotFoundException extends BusinessException {
    public NotFoundException(ErrorCode errorCode) { super(errorCode); }
}

public class InvalidRequestException extends BusinessException {
    public InvalidRequestException(ErrorCode errorCode) { super(errorCode); }
    public InvalidRequestException(ErrorCode errorCode, String detailMessage) {
        super(errorCode, detailMessage);
    }
}

public class ForbiddenException extends BusinessException {
    public ForbiddenException(ErrorCode errorCode) { super(errorCode); }
}

public class ConflictException extends BusinessException {
    public ConflictException(ErrorCode errorCode) { super(errorCode); }
}

public class TooManyRequestsException extends BusinessException {
    public TooManyRequestsException(ErrorCode errorCode) { super(errorCode); }
}
```

### 계층 구조 요약

```
RuntimeException
└── BusinessException                   ← 모든 비즈니스 예외의 루트 (ErrorCode 보유)
    ├── NotFoundException               → 404
    ├── InvalidRequestException         → 400
    ├── ForbiddenException              → 403
    ├── ConflictException               → 409
    └── TooManyRequestsException        → 429 (Redisson 락 획득 실패 전용)
```

> **UnauthorizedException을 별도로 만들지 않는 이유:**
> 401 UNAUTHORIZED는 Spring Security 필터 체인(`JwtAuthEntryPoint`)에서 처리됨.
> 비즈니스 레이어에 도달하기 전에 차단되므로 `@ExceptionHandler` 대상이 아님.

## 4. GlobalExceptionHandler

```java
// global/exception/GlobalExceptionHandler.java
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    /** 비즈니스 예외 처리 */
    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<ApiResponse<?>> handleBusinessException(BusinessException e) {
        log.warn("BusinessException: code={}, message={}", e.getErrorCode().getCode(), e.getMessage());
        return ResponseEntity
            .status(e.getErrorCode().getHttpStatus())
            .body(ApiResponse.fail(e.getErrorCode(), e.getMessage()));
    }

    /** @Valid 유효성 실패 */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiResponse<?>> handleValidException(MethodArgumentNotValidException e) {
        List<FieldError> fieldErrors = e.getBindingResult().getFieldErrors();
        Map<String, List<Map<String, String>>> errors = Map.of(
            "errors", fieldErrors.stream()
                .map(fe -> Map.of("field", fe.getField(), "message", fe.getDefaultMessage()))
                .collect(Collectors.toList())
        );
        return ResponseEntity
            .badRequest()
            .body(new ApiResponse<>(false, errors, ErrorCode.INVALID_REQUEST.getMessage(),
                ErrorCode.INVALID_REQUEST.getCode()));
    }

    /** 잘못된 요청 바디 */
    @ExceptionHandler(HttpMessageNotReadableException.class)
    public ResponseEntity<ApiResponse<?>> handleHttpMessageNotReadable(HttpMessageNotReadableException e) {
        log.warn("잘못된 요청 바디: {}", e.getMessage());
        return ResponseEntity
            .badRequest()
            .body(ApiResponse.fail(ErrorCode.INVALID_ENUM_VALUE));
    }

    /** DB UNIQUE 제약 위반 */
    @ExceptionHandler(DataIntegrityViolationException.class)
    public ResponseEntity<ApiResponse<?>> handleDataIntegrityViolation(DataIntegrityViolationException e) {
        log.error("DB UNIQUE 위반: {}", e.getMessage());
        return ResponseEntity
            .status(HttpStatus.CONFLICT)
            .body(ApiResponse.fail(ErrorCode.POSTING_ALREADY_MATCHED));
    }

    /** 예상치 못한 서버 에러 */
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiResponse<?>> handleException(Exception e) {
        log.error("Unexpected error", e);
        return ResponseEntity
            .status(HttpStatus.INTERNAL_SERVER_ERROR)
            .body(ApiResponse.fail(ErrorCode.INTERNAL_ERROR));
    }
}
```

## 5. 도메인별 예외 발생 상황

### Auth

| 상황 | throw | ErrorCode |
|------|-------|-----------|
| 이메일 중복 | `ConflictException(DUPLICATE_EMAIL)` | 409 A001 |
| 로그인 실패 | `InvalidRequestException(INVALID_CREDENTIALS)` | 401 A002 |
| JWT 인증 필요 | `JwtAuthEntryPoint` (필터 처리) | 401 A003 |
| 토큰 만료 | `JwtAuthEntryPoint` (필터 처리) | 401 A004 |
| 토큰 유효하지 않음 | `JwtAuthEntryPoint` (필터 처리) | 401 A005 |
| 블랙리스트 토큰 | `JwtAuthEntryPoint` (필터 처리) | 401 A006 |

### Posting (케어 공고)

| 상황 | throw | ErrorCode |
|------|-------|-----------|
| 공고 없음 | `NotFoundException(POSTING_NOT_FOUND)` | 404 PO001 |
| 타인 공고 수정 | `ForbiddenException(POSTING_FORBIDDEN)` | 403 PO002 |
| 마감된 공고에 제안 | `InvalidRequestException(POSTING_CLOSED)` | 400 PO003 |
| 이미 매칭된 공고 수락 (DB UNIQUE) | `ConflictException(POSTING_ALREADY_MATCHED)` | 409 PO004 |

### Proposal (시터 제안)

| 상황 | throw | ErrorCode |
|------|-------|-----------|
| 제안 없음 | `NotFoundException(PROPOSAL_NOT_FOUND)` | 404 PR001 |
| 동일 공고 중복 제안 | `ConflictException(PROPOSAL_DUPLICATED)` | 409 PR002 |
| Redisson 락 획득 실패 | `TooManyRequestsException(PROPOSAL_LOCK_FAILED)` | 429 PR003 |
