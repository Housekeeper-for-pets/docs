## 설계 원칙

| 원칙 | 내용 |
|------|------|
| 비즈니스 에러 / 시스템 에러 분리 | `BusinessException` 계층과 미처리 `Exception` 계층을 핸들러에서 구분 |
| 에러코드 단일 정의 | 모든 에러는 `ErrorCode` enum 한 곳에서 관리. 코드 문자열 하드코딩 금지 |
| API 응답 코드 일관성 | enum 이름(내부 식별자)과 API 응답 `code` 필드를 분리해 클라이언트 계약 유지 |
| 401은 Security 필터에서 처리 | JWT 인증 실패는 `@ExceptionHandler` 도달 전에 `JwtAuthEntryPoint`에서 처리 |
| 429는 별도 예외 클래스 | Redisson 락 획득 실패는 `TooManyRequestsException`으로 분리 |

## 2. Exception 계층 구조

```java
// global/exception/BusinessException.java
@Getter
public class BusinessException extends RuntimeException {

    private final ErrorCode errorCode;

    public BusinessException(ErrorCode errorCode) {
        super(errorCode.getMessage());
        this.errorCode = errorCode;
    }

    /** 기본 메시지 대신 동적 메시지를 사용할 때 */
    public BusinessException(ErrorCode errorCode, String detailMessage) {
        super(detailMessage);
        this.errorCode = errorCode;
    }
}
```

```java
// 404
public class NotFoundException extends BusinessException {
    public NotFoundException(ErrorCode errorCode) { super(errorCode); }
}

// 400
public class InvalidRequestException extends BusinessException {
    public InvalidRequestException(ErrorCode errorCode) { super(errorCode); }
    public InvalidRequestException(ErrorCode errorCode, String detailMessage) {
        super(errorCode, detailMessage);
    }
}

// 403
public class ForbiddenException extends BusinessException {
    public ForbiddenException(ErrorCode errorCode) { super(errorCode); }
}

// 409
public class ConflictException extends BusinessException {
    public ConflictException(ErrorCode errorCode) { super(errorCode); }
}

// 429 — Redisson 락 획득 실패 전용
public class TooManyRequestsException extends BusinessException {
    public TooManyRequestsException(ErrorCode errorCode) { super(errorCode); }
}
```

### 계층 구조 요약

```
RuntimeException
└── BusinessException                   ← 모든 비즈니스 예외의 루트 (ErrorCode 보유)
    ├── NotFoundException               → 404
    ├── InvalidRequestException         → 400
    ├── ForbiddenException              → 403
    ├── ConflictException               → 409
    └── TooManyRequestsException        → 429 (Redisson 락 획득 실패 전용)
```

> **UnauthorizedException을 별도로 만들지 않는 이유:**
> 401 UNAUTHORIZED는 Spring Security 필터 체인(`JwtAuthEntryPoint`)에서 처리됨.
> 비즈니스 레이어에 도달하기 전에 차단되므로 `@ExceptionHandler` 대상이 아님.

## 3. ErrorResponse DTO

```java
// global/common/ErrorResponse.java
@Getter
public class ErrorResponse {

    private final String code;
    private final String message;
    private final String timestamp;
    private List<FieldErrorDetail> errors;   // @Valid 유효성 실패 시만 포함

    private ErrorResponse(String code, String message) {
        this.code = code;
        this.message = message;
        this.timestamp = LocalDateTime.now(ZoneId.of("Asia/Seoul")).toString(); // KST
    }

    public static ErrorResponse of(ErrorCode errorCode) {
        return new ErrorResponse(errorCode.getCode(), errorCode.getMessage());
    }

    public static ErrorResponse of(ErrorCode errorCode, String detailMessage) {
        return new ErrorResponse(errorCode.getCode(), detailMessage);
    }

    /** @Valid 유효성 실패 — 필드별 에러 목록 포함 */
    public static ErrorResponse ofValidation(List<FieldError> fieldErrors) {
        ErrorResponse response = new ErrorResponse(
            ErrorCode.INVALID_REQUEST.getCode(),
            ErrorCode.INVALID_REQUEST.getMessage()
        );
        response.errors = fieldErrors.stream()
            .map(e -> new FieldErrorDetail(e.getField(), e.getDefaultMessage()))
            .collect(Collectors.toList());
        return response;
    }

    @Getter
    @AllArgsConstructor
    public static class FieldErrorDetail {
        private final String field;
        private final String message;
    }
}
```

## 4. GlobalExceptionHandler

```java
// global/exception/GlobalExceptionHandler.java
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    /** 비즈니스 예외 처리 */
    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<ErrorResponse> handleBusinessException(BusinessException e) {
        log.warn("BusinessException: code={}, message={}", e.getErrorCode().getCode(), e.getMessage());
        return ResponseEntity
            .status(e.getErrorCode().getHttpStatus())
            .body(ErrorResponse.of(e.getErrorCode(), e.getMessage()));
    }

    /** @Valid 유효성 실패 */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidException(MethodArgumentNotValidException e) {
        return ResponseEntity
            .badRequest()
            .body(ErrorResponse.ofValidation(e.getBindingResult().getFieldErrors()));
    }

    /** 잘못된 요청 바디 (허용되지 않는 enum 값 등) */
    @ExceptionHandler(HttpMessageNotReadableException.class)
    public ResponseEntity<ErrorResponse> handleHttpMessageNotReadable(HttpMessageNotReadableException e) {
        log.warn("잘못된 요청 바디: {}", e.getMessage());
        return ResponseEntity
            .badRequest()
            .body(ErrorResponse.of(ErrorCode.INVALID_ENUM_VALUE));
    }

    /** DB UNIQUE 제약 위반 (MATCHING.posting_id 등) */
    @ExceptionHandler(DataIntegrityViolationException.class)
    public ResponseEntity<ErrorResponse> handleDataIntegrityViolation(DataIntegrityViolationException e) {
        log.error("DB UNIQUE 위반: {}", e.getMessage());
        return ResponseEntity
            .status(HttpStatus.CONFLICT)
            .body(ErrorResponse.of(ErrorCode.POSTING_ALREADY_MATCHED));
    }

    /** 예상치 못한 서버 에러 */
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleException(Exception e) {
        log.error("Unexpected error", e);
        return ResponseEntity
            .status(HttpStatus.INTERNAL_SERVER_ERROR)
            .body(ErrorResponse.of(ErrorCode.INTERNAL_ERROR));
    }
}
```

## 5. 도메인별 예외 발생 상황

### Auth

| 상황 | throw | ErrorCode |
|------|-------|-----------|
| 이메일 중복 | `ConflictException(DUPLICATE_EMAIL)` | 409 A001 |
| 로그인 실패 | `InvalidRequestException(INVALID_CREDENTIALS)` | 401 A002 |
| JWT 인증 필요 | `JwtAuthEntryPoint` (필터 처리) | 401 A003 |
| 토큰 만료 | `JwtAuthEntryPoint` (필터 처리) | 401 A004 |
| 토큰 유효하지 않음 | `JwtAuthEntryPoint` (필터 처리) | 401 A005 |

### User

| 상황 | throw | ErrorCode |
|------|-------|-----------|
| 사용자 없음 | `NotFoundException(USER_NOT_FOUND)` | 404 U001 |
| 타인 정보 수정 시도 | `ForbiddenException(USER_FORBIDDEN)` | 403 U002 |
| 닉네임 중복 | `ConflictException(NICKNAME_DUPLICATED)` | 409 U003 |
| 현재 비밀번호 불일치 | `InvalidRequestException(INVALID_CURRENT_PASSWORD)` | 401 U004 |

| 상황 | throw | ErrorCode |
|------|-------|-----------|

### Posting (케어 공고)

| 상황 | throw | ErrorCode |
|------|-------|-----------|

### Rental (렌탈)

| 상황 | throw | ErrorCode |
|------|-------|-----------|
| 용품 없음 | `NotFoundException(RENTAL_ITEM_NOT_FOUND)` | 404 R001 |
| 렌탈 내역 없음 | `NotFoundException(RENTAL_NOT_FOUND)` | 404 R002 |
| 재고 없음 | `ConflictException(RENTAL_OUT_OF_STOCK)` | 409 R003 |

### AI 기능

| 상황 | throw | ErrorCode |
|------|-------|-----------|
| Circuit Breaker OPEN | `BusinessException(AI_SERVICE_UNAVAILABLE)` | 503 AI001 |

## 6. 전체 에러코드 참조표

| code | ErrorCode (enum) | HTTP | 메시지 |
|------|------------------|------|--------|
| **A001** | DUPLICATE_EMAIL | 409 | 이미 가입된 이메일입니다. |

public ProposalResponse submitProposal(Long postingId, Long sitterId, ProposalRequest request) {
    String lockKey = "lock:proposal:" + postingId;
    RLock lock = redissonClient.getLock(lockKey);

    boolean acquired = false;
    try {
        acquired = lock.tryLock(3, 10, TimeUnit.SECONDS);
        if (!acquired) {
            throw new TooManyRequestsException(ErrorCode.PROPOSAL_LOCK_FAILED);
        }

        CarePosting posting = postingRepository.findById(postingId)
            .orElseThrow(() -> new NotFoundException(ErrorCode.POSTING_NOT_FOUND));
        if (posting.getStatus() != PostingStatus.OPEN) {
            throw new InvalidRequestException(ErrorCode.POSTING_CLOSED);
        }
        if (proposalRepository.existsBySitterIdAndPostingId(sitterId, postingId)) {
            throw new ConflictException(ErrorCode.PROPOSAL_DUPLICATED);
        }
        // ... 저장 로직
    } finally {
        if (acquired && lock.isHeldByCurrentThread()) lock.unlock();
    }
}

// MatchingService.java
public MatchingResponse acceptProposal(Long postingId, Long proposalId, Long guardianId) {
    SitterProposal proposal = proposalRepository.findById(proposalId)
        .orElseThrow(() -> new NotFoundException(ErrorCode.PROPOSAL_NOT_FOUND));

    try {
        // posting_id UNIQUE 위반 시 DataIntegrityViolationException → GlobalExceptionHandler에서 처리
        Matching matching = matchingRepository.save(Matching.confirm(postingId, proposalId, guardianId));
        matchingEventProducer.send("matching-confirmed", MatchingConfirmedEvent.of(matching));
        return MatchingResponse.from(matching);
    } catch (DataIntegrityViolationException e) {
        throw new ConflictException(ErrorCode.POSTING_ALREADY_MATCHED);
    }
}

## 8. 패키지 구조 반영

```
global/
├── exception/
│   ├── ErrorCode.java                    ← enum (이 문서 기준, 55개 에러코드)
│   ├── GlobalExceptionHandler.java       ← @RestControllerAdvice
│   ├── BusinessException.java            ← 최상위 (ErrorCode 보유)
│   ├── NotFoundException.java            → 404
│   ├── InvalidRequestException.java      → 400
│   ├── ForbiddenException.java           → 403
│   ├── ConflictException.java            → 409
│   └── TooManyRequestsException.java     → 429 (Redisson 락 획득 실패 전용)
└── common/
    ├── ApiResponse.java                  ← 공통 성공 응답 래퍼 { data, code, message }
    └── ErrorResponse.java                ← 에러 응답 { code, message, timestamp, errors[]? }
```

### ApiResponse 구조

```java
// global/common/ApiResponse.java
@Getter
@RequiredArgsConstructor
public class ApiResponse<T> {
    private final T data;
    private final String code;
    private final String message;

    public static <T> ApiResponse<T> ok(T data) {
        return new ApiResponse<>(data, "200", "OK");
    }

    public static <T> ApiResponse<T> created(T data) {
        return new ApiResponse<>(data, "201", "Created");
    }
}
```

**성공 응답 JSON 형태:**

```json
{
  "data": { "postingId": 10, "title": "말티즈 3박 4일 케어 구해요", "status": "OPEN" },
  "code": "201",
  "message": "Created"
}
```

> **ApiResponse vs ErrorResponse 비교:**
>
> | 구분 | 클래스 | 필드 | 사용 시점 |
> |------|--------|------|----------|
> | 성공 | `ApiResponse<T>` | `data`, `code`, `message` | 2xx 응답 |
> | 실패 | `ErrorResponse` | `code`, `message`, `timestamp`, `errors[]`(선택) | 4xx / 5xx 응답 |
>
> `status` 필드는 존재하지 않음. HTTP 상태 코드는 `ResponseEntity`의 status로만 전달.
